## Goal

Watch five likely travellers attempt the journey, and measure whether the
HodoMap page helps them more reliably than the operator's own site.

## Why

The core assumption is that travellers cannot reliably find the correct
departure, boarding point, and ticket link on operator sites. This test either
supports or refutes that. Watching people try is the evidence, not opinion.

## The core question

Can they find the correct departure, boarding point, and ticket link more
reliably using the HodoMap page than using the operator's site?

## Tasks

- [ ] Recruit five participants who match a likely traveller for this corridor,
      for example a tourist and a resident.
- [ ] Define the task: plan this specific journey, identify the exact boarding
      point, and reach the correct ticket purchase or contact action.
- [ ] Run each session twice, counterbalanced: once on the HodoMap page, once on
      the operator's own site. Vary which goes first across participants.
- [ ] Measure for each attempt: task completion, whether the boarding point was
      correct, time taken, and errors or wrong turns.
- [ ] Capture observations and direct quotes. Do not coach participants.
- [ ] Note any point where the HodoMap page misled or confused.

## Success signal

- On the HodoMap page, at least four of five participants complete the task with
  the correct boarding point and the correct ticket action, and do so more
  reliably than on the operator site.

## Acceptance criteria

- [ ] Five sessions completed and recorded.
- [ ] Task completion, boarding correctness, and time captured for both the
      HodoMap page and the operator site.
- [ ] A short findings note with the pass or fail signal and the top issues.

## Data and rights

- Do not retain participant personal data beyond what the test needs. Store notes
  without identifying details.

## Out of scope (provisional, do not build yet)

- Large-scale or quantitative studies.
- Analytics instrumentation in the page.
